Technology Architecture

API-first, modular, Tally-aware

Preferred initial stack keeps velocity high (workflow + DB layer) while remaining replaceable. Every external system talks through the Integration API — so GST portals, payment gateways, or a future ERP can be added without rewriting cores.

Option A — Rapid (recommended for pilot)

Zoho Creator / similar low-code for workflows + custom JS widgets for dashboards. Tally connector as a small Windows service. Fastest path to 30–50 client pilot.

Option B — Custom (scale path)

Node.js / NestJS + PostgreSQL + Redis queues + React dashboards. Same module boundaries. Migrate from Option A module-by-module if needed — API contracts stay stable.

How data flows

Example: Monthly GSTR-3B cycle

1

Trigger

Calendar job (e.g. 5th of month) creates workflow instances for all GST-RET clients for period Sep.

  • workflows row
  • checklist tasks
  • SLA clocks
2

Collect

WhatsApp/email templates request missing docs. Client portal uploads land in DMS with FY/service tags. Tally sync pulls purchase/sales.

  • messages
  • documents
  • tally_sync
3

Validate & automate

OCR extracts invoices. Recon engine matches Tally ↔ GSTR-2B. Green drafts GSTR-3B. Mismatches create Amber/Red exceptions.

  • exceptions
  • draft filing payload
4

Human gates

Staff clears Amber. CA clears Red + approves filing when gate requires. Action written to approvals + audit_logs.

  • approvals
  • audit_logs
5

File · archive · bill · next

Portal submit (assisted), ack PDF stored, invoice generated, payment link sent, next month workflow spawned.

  • filings
  • invoices
  • new workflows
